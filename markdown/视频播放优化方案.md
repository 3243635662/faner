# 视频播放体验问题分析与方案

先说结论:你现在遇到的"状态栏该藏不藏"的问题,本质上是**控件显示状态被当成了"手势 toggle 状态"来管理,而不是"每次进入播放器/每次切换视频都要显式重置为 false"**。这是个状态管理问题,不是播放器库选型问题。库选对了只是省事,选错了也能通过封装解决。

## 一、播放器库怎么选

你现在用的是 `video_player`(纯解码器,没有 UI)。业内常见组合:

| 方案 | 优缺点 |
|---|---|
| `video_player` + `chewie` | chewie 自带控件 UI,但**高度定制困难**(平板适配、手势区域、左右切换按钮这些 chewie 默认不支持,得魔改内部实现,反而更麻烦) |
| `video_player` + **自己封装控件层** | 前期多写一点代码,但完全掌控显示/隐藏逻辑、手势区域、平板横竖屏布局,长期维护成本更低 |
| `media_kit` | 基于 libmpv,解码能力更强(编解码器覆盖广、性能好),UI 同样要自己封装 |

**建议:`video_player`(或换成 `media_kit` 提升兼容性)+ 完全自定义控件层**。原因很直接——chewie 这类现成 UI 库解决的是"最快出一个能用的播放器"的问题,而你现在缺的恰恰是"细节体验"和"平板适配",这两点必须自己控制 View 层才能做好,用 chewie 只会让你在它的抽象上做二次改造,更痛苦。

如果你现在还没有音视频兼容性问题(编码格式播不了、卡顿),就不必换 `media_kit`,先把 UI/交互层做对。

## 二、核心状态设计(解决你说的 bug)

问题根源:控件可见性大概率是这样写的——

```dart
bool _showControls = true; // 或者从未在切视频时重置
```

正确做法是把"控件可见性"和"当前播放的是哪个视频"绑定,**每次视频源变化(无论是自动播放下一个,还是用户点击进入播放页)都强制重置为 false**,而不是保留上一次的显示状态。

```dart
class VideoPlayerState {
  final bool controlsVisible;
  final Timer? hideTimer;
}

class VideoControlsController extends ValueNotifier<bool> {
  // value 表示 controlsVisible
  VideoControlsController() : super(false); // 默认隐藏

  Timer? _autoHideTimer;

  void onEnterPlayer() {
    // 无论是手动点进来还是自动切下一个,统一走这个入口
    value = false;
    _cancelTimer();
  }

  void toggle() {
    value = !value;
    if (value) _startAutoHideTimer();
    else _cancelTimer();
  }

  void _startAutoHideTimer() {
    _cancelTimer();
    _autoHideTimer = Timer(const Duration(seconds: 3), () => value = false);
  }

  void _cancelTimer() {
    _autoHideTimer?.cancel();
    _autoHideTimer = null;
  }

  @override
  void dispose() {
    _cancelTimer();
    super.dispose();
  }
}
```

**关键点**:在你的"自动播放下一个视频"的逻辑里(大概率是 `VideoPlayerController` 的 `addListener` 监听 `isCompleted`,或者用 `just_audio`/`video_player` 的 completion 回调触发换源),**必须在换源成功后手动调用 `onEnterPlayer()`**,而不是依赖它"自然保持隐藏"。很多人这里漏掉了,导致状态栏在切视频后"意外地"沿用了上一个视频结束时的显示状态。

同理,用户从列表页点进播放页(`initState` 或路由跳转后)也要显式调用一次 `onEnterPlayer()`。**不要指望默认值能覆盖所有入口**——只要有一条路径没调用重置,这个 bug 就会复现。

## 三、控件交互结构(主流播放器标准手势)

```
┌─────────────────────────────┐
│  顶部栏(返回/标题/更多)      │ ← 淡入淡出
│                               │
│      [◀]    ▶/⏸    [▶]      │ ← 中间三连按钮(上一个/播放暂停/下一个)
│                               │
│  ━━━━━●━━━━━━━━━━ 00:12/03:45│ ← 底部进度条
└─────────────────────────────┘
     整个视频区域 = GestureDetector(onTap: toggle)
```

实现要点:

```dart
GestureDetector(
  behavior: HitTestBehavior.opaque,
  onTap: () => controlsController.toggle(),
  child: Stack(
    children: [
      VideoPlayerWidget(controller: videoController), // 视频本体铺满
      ValueListenableBuilder<bool>(
        valueListenable: controlsController,
        builder: (context, visible, child) {
          return AnimatedOpacity(
            opacity: visible ? 1.0 : 0.0,
            duration: const Duration(milliseconds: 200),
            child: IgnorePointer(
              ignoring: !visible, // 隐藏时不拦截手势,避免"看不见但能点到"
              child: child,
            ),
          );
        },
        child: ControlsOverlay(...), // 顶部栏+中间按钮+底部进度条
      ),
    ],
  ),
)
```

**易踩的坑**:`AnimatedOpacity` 只改变透明度,不改变可点击性,控件"看不见但还占着热区"会挡住下面的视频点击。一定要配合 `IgnorePointer` 或者干脆用 `Visibility(maintainState: true)` 控制。

左右切换按钮点击时**不要触发 toggle**,记得给按钮单独包一层 `GestureDetector` 并 `absorbHit`,或者干脆把按钮放在 `ControlsOverlay` 内(它本身已经是可点击区域,配合外层 `HitTestBehavior.opaque` 的判断顺序,子 widget 的 `onTap` 会优先响应,不会冒泡到外层的整屏 toggle)。

## 四、平板适配(参考"文件极客" Files by Google)

Files by Google 在平板上视频预览的做法本质是**响应式断点 + 手势区域按屏幕比例划分**,不是什么特殊组件。你项目 README 里已经写了自己有断点系统(`lib/core/tokens.dart`),直接复用即可:

- **横屏/宽屏(平板横放、桌面模式)**:播放器居中,两侧留黑边或显示播放列表侧栏(参考 YouTube 平板横屏的"视频+右侧队列"布局),而不是让视频硬拉伸铺满导致变形。
- **控件尺寸**:平板上手指触控热区不能照搬手机的 44dp,按钮间距、进度条 thumb 大小要按屏幕宽度做等比缩放或设最小值。
- **方向锁定**:视频全屏播放时建议 `SystemChrome.setPreferredOrientations` 跟随视频宽高比自动建议横屏,但不要强制锁死用户方向(平板用户很多时候习惯竖持看内容再横屏看视频)。
- **状态栏这里说的"隐藏"如果是指系统状态栏**(而不是你的控件栏),记得配合:

```dart
// 进入播放页,隐藏系统状态栏和导航栏
SystemChrome.setEnabledSystemUIMode(SystemUiMode.immersiveSticky);

// 退出播放页恢复
SystemChrome.setEnabledSystemUIMode(SystemUiMode.edgeToEdge);
```

如果你说的"状态栏"其实是指**你自定义的顶部播放控制条**(标题栏+返回按钮那一条),那就完全归入上面第二节的 `controlsController` 统一管理,和系统状态栏是两回事,但建议两者**同步显隐**(用户点一下,系统状态栏和你的自定义顶部栏一起出现/消失),这也是抖音、B站这类主流 App 的标准做法,体验上更统一。

## 五、建议的文件结构

```
lib/features/media_viewer/
├── video_player_page.dart          # 页面壳,负责路由参数、方向控制、生命周期
├── controllers/
│   └── video_controls_controller.dart  # 上面的 ValueNotifier
├── widgets/
│   ├── video_surface.dart          # 纯播放画面 + 手势捕获层
│   ├── controls_overlay.dart       # 顶部栏 + 中间三按钮 + 底部进度条
│   ├── progress_bar.dart
│   └── prev_next_buttons.dart
└── playlist_provider.dart          # Riverpod 管理"当前播放索引/自动切下一个"逻辑
```

把"切换视频"这个动作收敛到 `playlist_provider` 里一个统一的方法(比如 `playNext()` / `playAt(index)`),无论是自动触发还是用户点按钮触发,都走这一个入口,并在这个方法里调用 `controlsController.onEnterPlayer()`。这样能从架构上杜绝"某个路径忘记隐藏控件"的问题,而不是靠到处补丁。
